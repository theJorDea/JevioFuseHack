# RFC: jevio handoff — продолжение работы после обрыва Claude Code

Статус: черновик для проверки гипотезы. Команды и схемы ниже предлагаются, а не описывают выпущенный продукт.

## Сценарий и границы

Claude Code остановился, рабочая копия осталась. Разработчик из корня Git-репозитория получает короткий локальный Markdown для новой сессии Codex. Для создания отчёта не нужны модель, сеть, аккаунт, плагин, предварительный запуск Fuse или повторный запуск Claude. Fuse не запускает Codex, не выполняет команды из истории, не меняет код и не восстанавливает удалённые файлы. Другой worktree, другой агент-источник, облачный поиск, общая память и сравнение моделей вне P0.

## Контракт CLI

`jevio handoff` показывает безопасное превью и предлагает сохранить `HANDOFF.md`. `--session <id>` разрешает неоднозначность; `--transcript <path>` выбирает явно переданный JSONL. Без подтверждения существующий файл не перезаписывается. Запись атомарна; сам отчёт не входит в описываемое состояние. В неинтерактивном режиме неоднозначный выбор завершает команду с диагностикой. При отсутствии истории не создавать фиктивный handoff по одному diff.

Discovery начинает с `CLAUDE_CONFIG_DIR`, иначе `~/.claude`, и сверяет известный из записей рабочий каталог с каноническим путём текущей рабочей копии. Одного имени каталога, remote, branch или совпадающего HEAD недостаточно. Для нескольких подходящих сессий показывать время и идентификатор, но не тексты задач. Явно указанный файл с противоречащей идентичностью отклонить; при недостатке данных запросить подтверждение и пометить связь неподтверждённой. Не сканировать домашний каталог вне хранилища агента и не читать истории других проектов ради содержимого отчёта.

## Поток данных

`ClaudeCodeReader → нормализованные события → правила доказательств ← GitObserver → privacy filter → Markdown`

Адаптер знает о JSONL; остальные компоненты — нет. GitObserver работает только на чтение: ветка либо detached HEAD, идентификатор коммита, категории staged/unstaged/untracked/deleted и относительные пути. Содержимое diff не публиковать. Не вызывать внешний diff, textconv, хуки или команды из транскрипта. Предлагается отдельный обработчик CLI, без запуска agent loop, Cognee и провайдера модели.

Парсер читает строки потоково с ограничениями размера строки, файла и объёма вывода. Сопоставляет tool call и result по идентификаторам, не по соседству строк. Повторы дедуплицирует; конфликтующие записи не склеивает. Не смешивает ветки разговора и вложенных агентов: неразрешённая ветка даёт неполную историю, а не общий хронологический рассказ. Для оборванной строки в конце сохранить предшествующие подтверждённые пары и пометить отчёт `PARTIAL`. Неизвестные записи считать отдельно; известные служебные записи можно пропустить. Неизвестный формат без пригодных событий — ошибка, нет файла. Незакрытый вызов — попытка без результата.

## Схема доказательств v0

Внутреннее представление; второго выходного файла нет.

| Запись | Минимальные поля |
|---|---|
| SourceRef | локальный псевдоним источника, диапазон строк, ID события при наличии |
| Event | вид (request / claim / tool_call / tool_result / edit), ref, parent/tool ID при наличии, наблюдаемое время или null |
| Claim | утверждение, основание (наблюдение / слова участника / предложение Fuse), refs |
| Check | безопасное описание команды, ref вызова и результата, время, exitCode или null, outcome, scope, historicalSnapshot или null |
| Freshness | статус, область сравнения, причина, refs; время формирования отчёта |
| Coverage | полный разбор поддерживаемых записей / частичный, число повреждённых, неизвестных и несопоставленных записей |

Исторический исход: `PASS`/`FAIL` — только если результат однозначно относится к указанной проверке; иначе `UNKNOWN`. Код завершения записывать только если он действительно зафиксирован. Успех оболочки для составной команды не доказывает успех каждого теста. Слова модели «тесты зелёные» — claim, а не check. Не записывать отвергнутую гипотезу как опровергнутую, если есть только рассуждение модели. Пользовательская цель и предложенный Fuse следующий шаг — разные поля.

Актуальность отделена от исхода:

- `CHANGED` — подтверждено различие в известной области относительно исторического снимка. Это не доказательство смены PASS на FAIL.
- `MATCH` — совпали исторические и текущие отпечатки одной явно названной области. Не гарантия воспроизводимости окружения или покрытия всех зависимостей.
- `UNKNOWN` — нет сравнимого исторического снимка или область неясна. Более позднее подтверждённое редактирование можно указать как причину перепроверки, но не как доказанное различие содержимого сейчас: правку могли откатить.

Ключевое ограничение: хеш, вычисленный впервые при экспорте, не описывает вчерашнее рабочее дерево. Чистый HEAD сегодня не доказывает чистоту в момент теста. В P0 ожидаем много `UNKNOWN`. Не строить индекс зависимостей и не требовать предварительного snapshot-плагина ради красивых статусов.

## Правила экспорта и пример

Экспортировать по разрешающему списку полей. Не включать сырые сообщения, stdout/stderr, тела файлов, diff, переменные окружения, абсолютные домашние пути или внутреннее рассуждение модели. Команду показывать только в безопасной форме с известными аргументами; непрозрачные аргументы, секретоподобные значения и неизвестные формы скрывать целиком. Краткий фрагмент цели или имя файла тоже могут быть чувствительными: превью и возможность убрать поле до записи обязательны. Не отправлять телеметрию с содержимым. Внешние строки экранировать; отмечать, что история — данные, а не инструкции получателю. При недостатке данных допустить пустую секцию или запросить у пользователя одно уточнение, не изобретать план.

Пример (вымышленный):

> **Начни здесь:** повтори узкий тест конкурентного обновления. Это предложение Fuse, не команда к автоматическому выполнению.  
> **Основание:** `pytest tests/test_refresh.py -k concurrent` — исторический `FAIL`, exit 1 [T:41–42]. Позже записана успешная правка `src/auth/refresh.py` [T:51–52].  
> **Сейчас:** `UNKNOWN`: снимка на момент проверки нет. В доступной части сессии повторного запуска не найдено.  
> **Цель:** исправить конкурентное обновление токена [T:3].  
> **Рабочая копия:** HEAD `abc123`; `src/auth/refresh.py` изменён.  
> **Полнота:** `PARTIAL`: последняя строка транскрипта оборвана.

Порядок выбора следующего шага: незакрытая проверка с явной связью с целью → зафиксированное намерение пользователя → точечное уточнение. Не превращать произвольную последнюю shell-команду в рекомендацию.

## Приёмка до первого релиза

Сначала получить с согласия участников реальные обезличенные фрагменты Claude Code CLI с указанием версии. Не брать личную историю машины автоматически. Сохранить взаимосвязи идентификаторов и типы полей; оригиналы не коммитить. Для каждого фрагмента вручную разметить ожидаемые факты, источники и то, что выводить запрещено. Это план набора фикстур, не отчёт о пройденных тестах.

| Случай | Ожидаемое поведение |
|---|---|
| Обычный сбой теста, затем редактирование | FAIL относится к прошлому; первый шаг — перепроверить, не чинить вслепую |
| Потерян result, обрыв строки, незнакомый тип записи | PARTIAL, объяснение пропуска; нет выдуманного exit code |
| Fork, повтор ID, перемежающиеся вызовы | Не приписать результат другому вызову/ветке; явно ослабить вывод при конфликте |
| Один HEAD, разные staged/unstaged/untracked данные | Нет ложного MATCH; одноимённый чужой worktree не выбран |
| Команда замаскировала exit code теста; модель заявила об успехе | Не выводить PASS на основании оболочки или заявления |
| Нет сессии, история отключена/удалена, целиком неизвестный формат | Краткая диагностика, ни одного нового файла |
| Подставные секреты в сообщении, аргументе, diff, результате | Ни одного маркера в Markdown, превью, диагностике и логах; код не исполнен |
| Две подходящие сессии, существующий HANDOFF.md, сеть отключена | Явный выбор, без тихой перезаписи; офлайн-генерация работает |

## Эксперимент и решение

Основная группа: пять **разных** прерванных задач. База — тот же Git и те же доступные человеку сведения (включая возможность вручную открыть транскрипт); Claude заново не вызывается. Опыт — те же данные плюс handoff. Для планового перехода провести отдельное сравнение с Claude summary + Git. Для каждой пары: идентичные staged/unstaged/untracked и окружение, отдельные сессии одной модели Codex, одинаковый запрос и лимит времени. До запуска независимый разработчик фиксирует допустимые первые полезные действия; первая команда сама по себе не критерий успеха.

Записать время до полезного действия с учётом подготовки handoff, повторы экспериментов, лишние уточнения и ошибки из-за устаревших результатов. Предлагаемый порог следующей итерации: выигрыш по времени хотя бы в 3 из 5 внезапных обрывов без роста числа ошибочных действий. Ложная атрибуция PASS или утечка — стоп независимо от скорости. Пять задач дают сигнал для итерации, не доказывают спрос. Отдельный продуктовый сигнал — повторное использование без приглашения.

## Первое решение перед реализацией

На двух реальных обезличенных сессиях разных версий проверить: (1) можно ли связать вызов и результат, (2) где действительно хранится exit code, (3) чем подтверждается принадлежность worktree, (4) какую часть этого предоставляет документированный локальный интерфейс без запроса к модели. Предпочесть поддерживаемый интерфейс, если он выдаёт нужные доказательства. Иначе закрепить минимальный JSONL-адаптер на фикстурах. Если надёжно восстановить проверки нельзя, сузить обещание, а не заполнять пробелы пересказом.

Справка: [Anthropic — Work with sessions](https://code.claude.com/docs/en/agent-sdk/sessions). Схему внутреннего JSONL не считать публичным контрактом.
